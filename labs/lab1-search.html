Lab 1 — Search

Four algorithms, one problem class, and the measurements that tell them apart. By the end you will be able to say which search to run and why, with numbers.

Dr. Gorkem Kar Due: end of week 4 Weight: 4% of the course grade Individual work

What you are building

A search library and a study of it. One program, four frontier disciplines, and a written comparison that a reader could use to choose between them without running anything.

The environment is a weighted grid, released with the assignment. It has walls, a start cell, a goal cell, and eight-way movement with diagonal costs that are not the same as straight costs. Do not change the grid: the point is to compare algorithms on identical input.

Before you start

  • Module 2 (uninformed search) and module 3 (informed search).
  • AIMA 3.1–3.6, at least the sections on frontier disciplines and admissibility.
  • The maps in ../data/lab1/: grid_a.txt, grid_b.txt and grid_c.txt, plus trace_example.txt (a worked trace on grid a) and reference_results.csv (all four algorithms on all three maps) to check your counts against. ../data/README.md documents the grid format.
  • Python help for this lab: heapq for the priority queues, collections.deque for the FIFO queue, and argparse for the command line. More on the labs page.

Any language is acceptable, but the program must be callable from the command line with the interface in what the grader runs below. That interface is not relaxed, because it is how the grader calls you.

Tasks

1. One algorithm, four disciplines

Write search(problem, frontier) once, following the generic graph search from module 2, and implement the frontier as four interchangeable objects: FIFO queue, LIFO stack, priority queue on g, priority queue on g + h. Depth-first must use a stack; do not simulate one with recursion and call it the same thing.

Your implementation must report, for every run: the solution path, its cost, the number of nodes expanded, the number of nodes generated, and the maximum frontier size.

2. Three heuristics

Implement Manhattan distance and Euclidean distance to the nearest goal. Then implement the octile distance that matches the grid's diagonal costs. Report which of the three are admissible for this problem and prove it in one paragraph each — a proof, not an assertion. State clearly which one is inadmissible and what that does to A*'s guarantee.

3. Measure

Run all four algorithms on all three grids. They are deterministic apart from tie-breaking; if you break ties randomly, run three seeds and report the spread. Produce one table with a row per (grid, algorithm) and columns for solution cost, nodes expanded, nodes generated, and peak frontier size. Then produce the figure that actually matters: nodes expanded against solution depth, one line per algorithm.

4. Break it deliberately

Take the heuristic that is admissible but inconsistent on your grid, if you can construct one — a heuristic that never overestimates but can drop sharply between neighbours. Show A* returning a suboptimal path when the explored set is kept, and the same A* returning the optimal path when stale frontier entries are allowed to be re-expanded. Explain the difference.

Deliverables

  • Code — the library, the four frontier implementations, the two scripts that reproduce your tables and figures.
  • Reproduction file — one command that regenerates every number in your report. If it does not run, the numbers are not believed.
  • Written report, 4–6 pages — the comparison, the three admissibility proofs, and the inconsistency experiment. This is a quarter of the mark and it is where the grade usually separates.

Submit code and report together. The report is what a colleague reads to decide which algorithm to use; write it for that reader.

What the grader runs

One command per grid and algorithm, with a single JSON object on stdout: 

python3 search.py --grid ../data/lab1/grid_a.txt --algorithm astar

{"algorithm": "astar", "cost": 30.5, "expanded": 101, "generated": 161,
 "peak": 55, "path": [[1, 1], [0, 2], [0, 3], ...]}

That is the real row for grid_a and A*: it matches reference_results.csv exactly.

--algorithm is one of bfs, dfs, ucs, astar. A* must default to the octile heuristic: the grader does not pass --heuristic, so make it an optional flag with octile as the default. The grader runs all twelve combinations and compares cost, expanded, generated and peak against reference_results.csv. A mismatch is a bug in your search, not a different convention. Print nothing else to stdout — diagnostics go to stderr.

The grader passes absolute paths, so do not assume your program sits beside the data. To check yourself before submitting, run all twelve combinations and compare your four counts with the matching row of reference_results.csv; that is exactly the comparison the grader makes.

How it is graded

ComponentWeightWhat earns full marks
Correctness40%All four algorithms return optimal where they should, and the reported counts match an independent trace
Design20%One search function, four frontiers; no duplicated algorithm bodies
Measurement15%Tables reproduce; the figure is readable and its axes are labelled with units
Written analysis25%Proofs are proofs; the inconsistency experiment is explained, not just demonstrated

A working implementation whose report says nothing earns a C. That is stated in week one and it is not a surprise at grading time.

Rules

Individual work. You may discuss the algorithms with classmates; the code you submit must be yours, and you must be able to explain any line of it in a viva if asked. The syllabus late policy applies: 10% off per day for up to three days, then not accepted.

AI assistants: permitted for boilerplate, plotting, and debugging help, subject to the course's disclosure rule — state in the report which tool you used and for what. They are not permitted to write your analysis, and an undisclosed generated report is an integrity matter.

Check yourself before submitting

  • Does BFS return a costlier path than uniform cost on these grids, where steps cost different amounts, and can you say why?
  • Does A* expand no more nodes than uniform cost with an admissible heuristic, on every grid?
  • Does your peak frontier size for breadth-first exceed depth-first's on the open grid, and can you explain why from how each frontier grows?
  • Can you point to the line in your code where the four algorithms differ?
  • Does your reproduction command work from a clean checkout?
