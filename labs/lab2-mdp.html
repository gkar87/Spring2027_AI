Lab 2 — Planning under uncertainty

Value iteration and policy iteration on a slippery gridworld, and the argument for choosing one over the other.

Dr. Gorkem Kar Due: end of week 6 Weight: 5% of the course grade Individual work

What you are building

A planner. Given a gridworld with stochastic transitions, a reward function, and a discount factor, your program must produce an optimal value function and an optimal policy — by both iteration methods — and report what each one cost.

The grid slips: with probability equal to the slip parameter, an intended move goes perpendicular to the intended direction. Slip probability, discount, and grid layout are all command-line parameters. Nothing may be hard-coded to one map.

Before you start

  • Module 6, especially the Bellman equations and the policy improvement theorem.
  • AIMA 17.1–17.2.
  • The four maps in ../data/lab2/worlds/ — open6, corridor, cliff and wall_adjacent, the last with its terminal in a walled corner. ../data/README.md documents the world format.
  • Python help for this lab: json to read the worlds, and NumPy for absolute beginners if you solve the linear system with arrays. More on the labs page.

Tasks

1. Value iteration

Implement value iteration with a configurable convergence threshold. Report the number of sweeps to convergence and the maximum Bellman residual at each sweep. Convergence must be measured, not assumed: stop when the residual is below the threshold, and record the sweep count.

2. Policy iteration

Implement policy evaluation (solving the linear system, or iterating to a tight threshold — say which you did and why) followed by policy improvement, until the policy stops changing. Report the number of improvement rounds and the number of evaluation sweeps each round.

3. Compare

For each map, and for slip probabilities from 0.0 to 0.4 in steps of 0.1, record iterations to convergence and wall-clock time for both methods. Produce a table and one figure. Then answer, in prose: at what slip probability does the optimal policy change, and which cells change first? That is the interesting question, and it is worth more than the table.

4. Discount sensitivity

Fix one map. Vary the discount from 0.5 to 0.99. Show how the optimal policy and the value scale change. Explain the effect in terms of the horizon the discount implies — an effective horizon of roughly 1/(1 − γ) is a useful approximation to state and then to justify.

Deliverables

  • Code for both planners, plus the experiment driver.
  • Reproduction file that regenerates every table and figure.
  • Written report, 4–6 pages, including the policy-change analysis and the discount discussion.

What the grader runs

python3 plan.py --world ../data/lab2/worlds/open6.json --method vi \
    --gamma 0.9 --slip 0.1 --threshold 1e-6

{"method": "vi", "sweeps": 24, "residual": 6.7e-07,
 "values": [[0.45, 0.56, 0.68, 0.82, 0.98, 1.0], ...],
 "policy": [["E", "E", "E", "E", "E", null], ...]}

Those are the real numbers for open6 at γ = 0.9 with a 1e-6 threshold: 24 sweeps, a residual of 6.7 × 10⁻⁷, and the first row of the value table above. The worst-case bound, 0.9k < 10⁻⁶, predicts about 130 sweeps; the measured count is far lower, so report what you measured, not what you expected.

--method is vi or pi. Rather than compare against one stored policy, the grader checks three properties on every map: both methods return the same value function, your values satisfy the Bellman equation to within 1e-4 when substituted back, and your policy is greedy with respect to those values. A planner that passes all three is correct whatever its internals look like — which also means you may choose how to solve the linear system.

Array convention. values is a rows × cols array: null for a wall, the terminal's own reward at a terminal cell, and the value everywhere else. policy is the same shape with "N", "E", "S", "W" or null. Paths are passed to you absolute.

To check yourself before submitting, reproduce the open6 numbers above, then substitute your values back into the Bellman equation on every map: the largest difference should be below 1e-4, and value and policy iteration should agree.

Rules

Individual work. The syllabus late policy applies: 10% off per day for up to three days, then not accepted. Disclose any AI tool use as the syllabus requires; the analysis must be yours.

Check yourself before submitting

  • Do both methods agree to within your threshold on all four maps?
  • Does value iteration converge faster in sweeps but slower in seconds, or the reverse — and can you say why?
  • With slip 0, does your policy match the shortest-path policy you would draw by hand?
  • As γ → 1, does the value function grow in the way the horizon argument predicts?
  • Does the planner handle a map where the greedy move is blocked by a wall?
