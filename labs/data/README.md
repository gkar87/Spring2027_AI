# Lab starter data

Everything the six lab sheets refer to. The files are fixed for the semester, so
every number in a lab report is reproducible. Most were generated by the scripts in
the same folders, deterministically: running a generator again produces byte-identical
files. You do not need to run them, except Lab 5's: the course download leaves out
`dataset.bin` to stay small, so run `make_dataset.py` once before Lab 5. It
rebuilds the same file, byte for byte, in a few seconds.

```bash
cd labs/data/lab4 && python3 make_networks.py   # Bayesian networks + HMM sequence
cd labs/data/lab5 && python3 make_dataset.py    # 10,000 images (about 8 seconds)
cd labs/data/lab6 && python3 make_corpus.py     # corpus, questions, answer key
```

Lab 1's maps ship without their generator, because it contains a working solution
to the lab. Lab 2 and lab 3 have no generator: the worlds are hand-written JSON and
`qenv.py` is the environment itself.

Nothing here needs a third-party package. The generators use only the Python
standard library, so a student with a bare interpreter can regenerate any file.

## lab1 — search

| File | What it is |
|---|---|
| `grid_a.txt`, `grid_b.txt`, `grid_c.txt` | 15 × 27 maps. `a` is braided and open, `c` is close to a perfect maze. |
| `trace_example.txt` | Reference traces on `grid_a`: depth-first, uniform cost and A* with path costs, expansions, generations and peak frontier size. |
| `reference_results.csv` | All four algorithms on all three maps: path cost, nodes expanded, nodes generated, peak frontier, path length. Your report must reproduce this table. |

**Grid format.** Six comment lines, then one character per cell:
`#` wall, `.` cost 1, `,` cost 2, `;` cost 3, `S` start, `G` goal.

> **Parse this carefully.** A comment line begins with `# ` — a hash *and a space*.
> A map row never does, because its wall cells are a run of `#` with no space. If your
> parser skips every line starting with `#`, it will discard the whole map and report
> an empty grid. That is the most common first bug in lab 1.
Movement is 8-directional; entering a cell costs that cell's cost, multiplied by
1.5 for a diagonal move. The start cell is free; the goal cell is charged when
entered. Corner-cutting between two diagonal walls is allowed.

Neighbours are generated in the order N, NE, E, SE, S, SW, W, NW, and ties are
broken by insertion order. `reference_results.csv` depends on both conventions, so
match them or your node counts will differ on ties.

The goal of each map is the cell farthest from the start by step count, so no map
can be solved by walking along an edge.

`reference_results.csv` is the interesting part: it is a ground truth produced by
an implementation that is not yours, which is what makes "my counts differ"
a debuggable question rather than an argument.

## lab2 — planning

`worlds/` holds four JSON specifications:

| World | Shape | What it tests |
|---|---|---|
| `open6.json` | 6 × 6 open room | Slip makes the diagonal route a bet; the optimal policy is not the shortest path. |
| `corridor.json` | 3 × 12 corridor, no slip | Values propagate exactly one cell per sweep; convergence is countable by hand. |
| `cliff.json` | 8 × 8 with a −1 terminal strip | Local optima and the cost of risk. |
| `wall_adjacent.json` | 5 × 5, terminal in a walled corner | Blocked moves must leave the agent in place rather than move it elsewhere. |

**World format**

```json
{
  "name": "open6",
  "rows": 6, "cols": 6,
  "walls": [[0, 0], [1, 3]],
  "start": [5, 0],
  "terminals": { "0,5": 1.0 },
  "step_reward": -0.04,
  "slip": 0.1
}
```

A terminal entry maps a cell to its reward, and ends the episode.

**Terminal reward convention (lab 2).** Every move earns `step_reward`, including
the move into a terminal. A terminal is a state whose value is fixed at its reward
`R`, so entering it is worth `step_reward + γ·R`: the terminal reward is discounted
once, as in the week 6 playground and the midterm. The lab 2 grader uses this
convention. `qenv.py` (lab 3) instead returns `R` as the reward of the step that
enters the terminal; on these four worlds at γ = 0.9 the two conventions give the
same optimal policy, so the lab 3 comparison is unaffected.
`slip` is the probability that a move goes perpendicular to the intended
direction, split evenly between the two perpendicular directions.

## lab3 — reinforcement learning

`qenv.py` is the black-box environment: `GridEnv(world, seed)` with `reset()`,
`step(action)` returning `(state, reward, done)`, `state_index(state)`,
`n_states` and `n_actions`. Actions are 0 = N, 1 = E, 2 = S, 3 = W.

It loads the lab 2 worlds, so the policy you learn can be compared with the policy
you computed. How an action becomes a transition is private. Reading `_spec` or
re-deriving the transition probabilities invalidates the submission — the point of
the lab is that the learner never sees the model.

```bash
python3 qenv.py ../lab2/worlds/cliff.json --episodes 5 --seed 3
```

## lab4 — inference

| File | Variables | Why it is here |
|---|---|---|
| `alarm.json` | 5 | Small enough to check every number by hand. The textbook network. |
| `chain20.json` | 20 | Enumeration is 2^19 terms; elimination with a good order is linear. |
| `dense.json` | 8 | Every variable depends on all earlier ones, so no elimination order is cheap. |

**Network format.** Variables are binary with states `false`, `true`. Each CPT row
is the distribution given one parent configuration; rows step through parent
configurations in binary counting order with the **first parent as the most
significant bit**, and the last entry of each row is P(variable = true).

For `Alarm` with parents `[Burglary, Earthquake]` the rows are
(false,false), (false,true), (true,false), (true,true).

`hmm_params.json` holds a three-state, four-observation HMM;
`hmm_observations.txt` has 300 observations as integers indexing the observation
list; `hmm_first_step.json` gives the posterior after the first observation so you
can check your forward pass before running the whole sequence. The hidden sequence
is deliberately not provided.

## lab5 — deep learning

`dataset.bin` — 10,000 images of 28 × 28, ten classes, generated procedurally.

| Offset | Contents |
|---|---|
| 0 | 7,840,000 bytes of pixels, uint8, row-major |
| 7,840,000 | 10,000 bytes of labels, 0–9 |

```python
import numpy as np
raw = np.fromfile("dataset.bin", dtype=np.uint8)
x = raw[:7_840_000].reshape(-1, 28, 28)
y = raw[7_840_000:]
```

`dataset_meta.json` gives the class names, the count, and the fixed
train/validation/test split as indices into the flat dataset.

Classes are stroke patterns (circle, ring, square, triangle, cross, diagonal, bar,
ell, tee, dots) drawn with random rotation, scale, offset, line weight, background
brightness, occlusion and Gaussian noise. Two reference points measured on the
test split: majority class 9.5%, nearest centroid 53.3%. A network that cannot
beat 53% has a bug, not a hard problem.

Respect the split. Tuning against test makes the test set stop measuring anything.

## lab6 — retrieval-augmented QA

| File | Contents |
|---|---|
| `corpus.jsonl` | 252 passages, each `{"id", "text", "topic"}` |
| `questions.jsonl` | 73 questions, each `{"id", "question"}` |
| `answers.json` | The key: gold passage ids, a reference answer, and whether the question is answerable |

63 questions are answerable from the corpus and 10 are not — they ask about
material the corpus deliberately omits (model sizes, hardware, library defaults,
salaries). A system that answers those ten anyway is the failure this lab is built
to detect.

The key is for scoring only. Do not tune against it; if your reported numbers
cannot be regenerated from your code and the fixed question set, they are not
accepted.
