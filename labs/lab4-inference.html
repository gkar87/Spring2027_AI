Lab 4 — Inference

Exact inference by enumeration and by variable elimination, approximate inference by sampling, and the point where approximation stops being worth it.

Dr. Gorkem Kar Due: Sunday, April 11 (end of week 12) Weight: 5% of the course grade Individual work

What you are building

An inference engine for discrete Bayesian networks, built on a network specification file format you are given. It must answer queries of the form P(variable | evidence) four ways, and it must be correct before it is fast.

Three networks ship in ../data/lab4/: alarm.json (five nodes), chain20.json (twenty in a line) and dense.json (a clique). The dense one exists to punish enumeration, and the chain exists to reward elimination ordering. ../data/README.md documents the CPT row order, which is the part students get wrong first. Paths in this sheet are written from a folder of your own beside data, such as labs/lab4/; the labs page shows the layout.

Before you start

  • Module 9 (representation, independence, d-separation) and module 10 (inference, sampling, HMMs).
  • AIMA 13.3–13.4, 14.1–14.3 and 14.5.
  • Python help for this lab: itertools for looping over assignments, and classes for a factor object. More on the labs page.

Tasks

1. Enumeration

Implement inference by enumeration over the full joint distribution. It will be slow; that is the point of having it. Report the number of terms the sum expands to for each query, as a formula in the number of unobserved variables, and check the formula against a counted value.

2. Variable elimination

Implement variable elimination with factors. Support at least two orderings: the order given on the command line, and a greedy min-fill heuristic. Report, for each query, the number of multiplication and sum operations performed. Then state, with numbers, what the ordering bought you on the dense network.

3. Sampling

Implement rejection sampling and likelihood weighting. For one query on the alarm network, plot estimated probability against number of samples for both methods, on the same axes, with the exact answer drawn as a horizontal line. Then answer: at what sample count does rejection sampling become unusable as evidence grows, and why does likelihood weighting not suffer the same collapse?

4. Filtering

Implement the forward algorithm for an HMM and run it on the provided sequence — hmm_params.json and hmm_observations.txt, with hmm_first_step.json giving the first posterior so you can check the recursion before running 300 steps. Then implement particle filtering and compare. Report the effective sample size over time and the point at which resampling is required. The comparison should say when particles are the right tool and when the exact forward pass is simply better.

Deliverables

  • Code for all four methods plus the experiment driver.
  • Reproduction file regenerating every reported number and figure.
  • Written report, 5–7 pages: the operation counts, the sampling convergence plot, and the filtering comparison.

What the grader runs

python3 infer.py --net ../data/lab4/alarm.json \
    --query "Alarm" --evidence "JohnCalls=true,MaryCalls=true" --method ve

{"query": "Alarm", "p_true": 0.760692}

That number is worth checking. P(Alarm | John, Mary) = 0.7607, while P(Burglary | John, Mary) = 0.2842 — the well-known 0.284 in the textbook is the burglary posterior, not the alarm one. If your first answer is 0.284 you have the query right and the variable wrong, which is the most common single mistake in this lab.

--method is one of enum, ve, rejection or lw; add --samples N for the two sampling methods and --order to pin an elimination ordering. The two exact methods must agree to 1e-9 on the alarm network, and each sampling method is checked against that answer at five standard errors of its own estimate — which is why the report needs the standard error, not just the number. Operation counts are not graded; put them in your complexity table and report them honestly.

To check yourself before submitting, reproduce 0.760692 for the query above with both exact methods, and check your forward pass against hmm_first_step.json before running the whole sequence.

Rules

Individual work. The syllabus late policy applies: 10% off per day for up to three days, then not accepted. Disclose AI tool use. A library that performs Bayesian inference for you is not permitted — the point is to write the factors yourself. Numerical libraries for arrays and plotting are fine.

Check yourself before submitting

  • Do enumeration and elimination agree exactly on every query?
  • Does your operation count for elimination drop when the ordering improves?
  • Does likelihood weighting converge to the same answer with far fewer samples than rejection?
  • Does your particle filter's effective sample size fall before you resample?
  • Can you say which query on the dense network is intractable in practice, and why?
