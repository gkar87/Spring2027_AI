Lab 5 — Deep learning

A small convolutional network trained honestly: baseline first, overfit on purpose, then earn your way back to generalisation.

Dr. Gorkem Kar Due: Sunday, April 18 (end of week 13) Weight: 5% of the course grade Individual work

What you are building

An image classifier on ../data/lab5/dataset.bin — ten thousand 28 × 28 images in ten classes, with the fixed train/validation/test split recorded in dataset_meta.json. The split is fixed because the moment you tune against the test set, the test set stops measuring anything.

The course download leaves this file out to stay small. Make it once, before you start: in labs/data/lab5, run python3 make_dataset.py. It takes a few seconds, needs only the Python standard library, and builds exactly the same file for everyone.

The network must be small enough to train on a laptop CPU or a single modest GPU in minutes, not hours. This is deliberate: the lab is about the method, not about the hardware.

Before you start

  • Module 12, especially backpropagation, convolutional layers, and regularization.
  • AIMA 19.6–19.7 and 21.1–21.6.
  • A framework of your choice. You may use its layers and optimizers; you may not use a pretrained backbone. This is a from-scratch exercise.
  • Python help for this lab: Learn the basics (PyTorch), and probability calibration (scikit-learn) for the reliability diagram. More on the labs page.

The binary layout and the split file are documented in ../data/README.md, and the generator that produced the images ships beside the data, so you can check that you are reading the format the way it was written. Paths in this sheet are written from a folder of your own beside data, such as labs/lab5/; the labs page shows the layout.

Tasks

1. Baselines before models

Report the accuracy of two trivial baselines: always predicting the majority class, and a nearest-centroid classifier. Everything you build afterwards must be compared against these, and the report must show them on the same axes as your network. Beating chance is not a result; beating both baselines by a stated margin is. On the test split they score 9.5% (the training split's majority class) and 53.3% (nearest centroid); if yours differ, check them before going on.

2. Overfit a single batch

Before training on the full set, take one batch of 32 examples and train until the loss is essentially zero. If you cannot overfit 32 examples, your code is wrong — this is the cheapest debugging check in deep learning and it is worth doing first. Report the loss curve.

3. Train properly

Train a convolutional network with a sensible schedule. Report training and validation loss per epoch on one figure, and accuracy on another. Then vary three things one at a time — learning rate, weight decay, and augmentation or dropout — and report the effect of each. One variable at a time; an ablation table is not a grid search's leftovers.

4. Calibration and errors

Plot a reliability diagram for your best model on the validation set. Report the expected calibration error. Then examine the twenty highest-confidence errors: for each, say whether the image is genuinely ambiguous or the model is simply wrong, and what in the image likely caused it. This section is where most of the marks are, because it is where the thinking is.

Deliverables

  • Code and the trained weights of your best model.
  • Reproduction file that trains and evaluates from a clean checkout, with a fixed seed.
  • Written report, 5–7 pages: baselines, ablations, reliability diagram, and the error analysis.

What the grader runs

# the shape of the output — these numbers are placeholders, not targets
python3 train.py --data ../data/lab5 --epochs 20 --seed 0

{"val_acc": 0.00, "test_acc": 0.00, "ece": 0.00, "seed": 0}

Fill in your own numbers. Ship predictions.txt in your submission root — 1500 lines, one predicted class per test index in the order given by dataset_meta.json — and the grader finds it on its own; pass --predictions only if you put it somewhere else. It scores that file itself, so the reported accuracy is checked against your model rather than trusted.

The pass mark is 0.78 test accuracy on that file, set above the 0.53 nearest-centroid baseline rather than at it, since beating a trivial predictor is the minimum a network must earn. Your reported figure must match the file within 0.01. Below the baseline is not partial credit: it is a bug somewhere.

To check yourself before submitting, compute accuracy from your own predictions.txt and the test labels, the way the grader does, and make sure it matches the number your program prints.

Rules

Individual work. The syllabus late policy applies: 10% off per day for up to three days, then not accepted. Disclose AI tool use. No pretrained weights, no external labelled data, no test-set tuning. Report the seed and the exact command that produced your headline number.

Check yourself before submitting

  • Can you overfit 32 examples to near-zero loss?
  • Are both trivial baselines on your results figure?
  • Does validation loss ever rise while training loss falls — and did you say so?
  • Is your model's confidence better than its accuracy, or worse?
  • For your top-confidence error, can you describe what the model likely keyed on?
