Lab 3 — Learning from experience

Tabular Q-learning on the same gridworld you planned in, and an honest account of what it costs to learn what you could have computed.

Dr. Gorkem Kar Due: end of week 7 Weight: 4% of the course grade Individual work

What you are building

An agent that does not know the transition model. It moves, observes rewards, and updates a table. You will compare its learned policy with the optimal policy that lab 2 computed, and you will report the gap rather than hiding it.

The environment is ../data/lab3/qenv.py — a black box with a reset method and a step method, running the worlds from lab 2. You may read its rewards and its terminal flags; you may not read its transition probabilities. Any solution that inspects the model is worth zero regardless of the numbers it produces.

Before you start

  • Module 7, especially TD learning, the Q-learning update, and the exploration/exploitation trade-off.
  • AIMA 22.1–22.4.
  • Your lab 2 planner, which you will use only as a source of ground truth for the comparison.
  • Python help for this lab: NumPy random generators for seeding, and the pyplot tutorial for curves with a shaded band. More on the labs page.

Tasks

1. Q-learning

Implement tabular Q-learning with ε-greedy action selection. Every parameter — learning rate, ε, decay, episode cap — must come from a configuration file. Log the per-episode return and the number of steps, so the learning curve can be plotted without re-running training.

2. Exploration schedules

Compare three schedules: constant ε = 0.1; ε decaying linearly to zero over the first half of training; and ε decaying geometrically. Ten seeds each. Plot mean return with a shaded band for one standard deviation — a single-seed curve is not evidence, and the report will be read that way.

3. Compare with planning

After training, extract the greedy policy and compare it cell by cell with the optimal policy from lab 2. Report the fraction of cells where they agree, and list the cells where they differ. For each disagreement, say whether the difference is a learning failure (the value estimate is wrong) or a tie (both actions are optimal). Ties are not failures; conflating the two is the most common mistake in this lab.

4. Cost of learning

Count the environment interactions your agent needed to reach 95% of the optimal policy's return. Compare that with the number of transitions the planner needed to read. State the ratio plainly. Then argue, in a paragraph, when learning is worth that price — your argument should mention at least one situation where the model is unavailable.

Deliverables

  • Code for the agent, the schedules, and the experiment driver.
  • Logs from the ten-seed runs, or a reproduction file that regenerates them.
  • Written report, 4–6 pages, with the policy comparison and the cost-of-learning argument.

What the grader runs

python3 qlearning.py --config config.json --world ../data/lab2/worlds/cliff.json \
    --episodes 2000 --seed 3

{"episodes": 2000, "seed": 3, "return_mean": 0.60,
 "policy_agreement": 0.42, "interactions": 25547}

A real run: 2000 episodes on cliff with α = 0.1 and ε = 0.1 reaches a mean return of about 0.60 over the last hundred episodes, agrees with the optimal policy in roughly 42% of cells, and takes about 25 thousand steps. The low agreement is not a bug to hide — most of the disagreements are cells the agent rarely visits, and characterising them is task 3.

The configuration file holds α, ε and the schedule; flags on the command line override it, so one config can serve several seeds. The grader reruns your command with seeds 1, 2 and 3 and requires that the numbers you report fall inside the spread of those runs — a single flattering seed is visible in that comparison, which is the whole point of asking for ten.

Name your configuration file config.json in the submission root: the grader passes --config only when that file exists, and the command-line flags override whatever it contains.

To check yourself before submitting, run seeds 1, 2 and 3 with α = 0.1 and ε = 0.1. A correct learner using qenv.py lands close to the numbers above; the grader accepts a mean return within 0.15 of what real runs produce.

Rules

Individual work. The syllabus late policy applies: 10% off per day for up to three days, then not accepted. Disclose AI tool use. Reading the environment's transition table, however convenient, invalidates the submission.

Check yourself before submitting

  • Does your Q-table converge if you train for ten times longer, or does it oscillate?
  • Does the greedy policy visit the same cells as the planner's policy?
  • With ε fixed at 1.0, does the agent learn anything — and what does that tell you?
  • Are your curves the mean of ten seeds with a visible band?
  • Can you state the interaction count as a number, next to the planner's?
