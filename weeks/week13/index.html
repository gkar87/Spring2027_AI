Attention

Every position reads every other position in one step.

The problem attention solves

Recurrent networks process a sequence one step at a time. Two consequences: computation cannot be parallelized across positions, and information from far back must survive many steps.

Convolutions parallelize but only see a local window, so long-range dependencies need many layers.

Attention allows every position to read every other position in one step. That removes both limits at the cost of quadratic work in sequence length.

The trade, stated plainly

The trade, stated plainly
ArchitecturePath lengthParallel
RecurrentO(n)No
ConvolutionalO(log n) layersYes
AttentionO(1)Yes

Quadratic cost is why context windows are finite, and why efficient-attention variants are an active research area.

Tokens and embeddings

Text is split into subword tokens by an algorithm such as byte-pair encoding. Each token becomes an integer id, and each id indexes a learned vector.

  • Common words become one token; rare words split into pieces.
  • Vocabularies of tens of thousands of tokens are typical; languages that are rare in the training data get split into more, shorter tokens.
  • Token counts differ from word counts, which is why pricing is per token.
Why tokenization matters

"unbelievable" might be three tokens. Arithmetic on digits often fails because "1234" is not one token and the model never sees the number as a unit.

This is a real capability limit with a mundane cause, and it is a good example of how representation choices leak into behaviour.

Self-attention, in one equation

Attention(Q, K, V) = softmax( QK⊤ / √dk ) V

Each token produces a query, a key, and a value. The query is compared with every key to produce weights; the weights average the values.

It is a soft, differentiable lookup: "what am I looking for, what do I have, and what do I pass along?"

Why divide by √dk

Dot products of d-dimensional random vectors have variance growing with d. Large scores push softmax into saturation, where gradients vanish. Scaling by √d keeps the variance near 1.

Causal masking

For generation, a token must not attend to future tokens. Set those scores to −∞ before the softmax so their weights become zero.

Worked attention, three tokens

One head, dk = 2

Query for token 1: q = [1, 0]. Keys: k₁ = [1, 0], k₂ = [0, 1], k₃ = [1, 1]. Values: v₁ = [1, 0], v₂ = [0, 1], v₃ = [2, 2].

scores = [1, 0, 1] / √2 ≈ [0.71, 0, 0.71]

softmax ≈ [0.40, 0.20, 0.40]

output = 0.40·[1,0] + 0.20·[0,1] + 0.40·[2,2]
≈ [1.20, 1.00]

Read the result

Token 1 attends mostly to itself and to token 3, because its query aligns with both keys. Token 3's value dominates the output because its magnitude is larger.

Two observations worth keeping

  • Attention weights are a distribution: they sum to 1 across positions.
  • Attention is not "understanding". It is a weighted average, and the weights are learned.

One head captures one kind of relation. Multiple heads capture several in parallel.

The block: attention, feed-forward, and two shortcuts

x ← x + MultiHeadAttention(LN(x))
x ← x + FFN(LN(x))

Each sublayer is wrapped in a residual connection and preceded by layer normalization (pre-LN). The feed-forward network is two linear layers with a nonlinearity, applied identically to each position.

Most parameters live in the feed-forward layers, not in attention — typically about two thirds.

Position, and why attention needs it

Attention is permutation-equivariant: shuffle the input tokens and the outputs shuffle the same way. On its own it has no notion of order.

Position must therefore be injected — added to the embeddings, or encoded in the attention scores (as in rotary position embeddings).

Why this is not a minor detail

Without positional information, "dog bites man" and "man bites dog" are the same input. The model can still learn a great deal — it becomes a bag-of-tokens — and that is exactly the failure mode to watch for when debugging.

Rotary embeddings are a common modern choice. On their own they do not make a model reliable on sequences longer than it was trained on; that usually needs extra techniques or further training.

From predictor to assistant

Pretraining, post-training and RLHF.

Pretraining: predict the next token, at scale

The objective is next-token prediction on a large corpus — self-supervised, so no labels are needed beyond the text itself.

L = −Σt log P(xt | x<t)

Everything the model knows about language, facts, and reasoning is a side effect of getting very good at this. That is remarkable, and it is also why the model has no explicit representation of truth.

Scaling laws

Loss falls predictably as a power law in parameters, data, and compute. This predictability is why labs can plan a training run before starting it — and why "just make it bigger" was a rational strategy for several years.

The caveat: the law predicts loss, not capability. Emergent behaviour at scale is real but poorly predicted.

Post-training: from predictor to assistant

1 · Instruction tuning

Fine-tune on demonstrations of instruction–response pairs. Teaches format and compliance, not new knowledge.

2 · Preference model

Humans rank pairs of responses. Train a reward model to predict the preferred one.

3 · Preference optimization

Optimize the policy against the reward model, with a penalty for drifting from the starting model.

objective = E[ rφ(x, y) ] − β · KL( πθ ‖ πref )

The KL term is essential. Without it, the policy finds inputs where the reward model is simply wrong — the reward-hacking failure from module 7, with a learned reward.

What RLHF does, and what it cannot do

It does

  • Align output style with annotator preference.
  • Reduce obviously unhelpful or hostile responses.
  • Make the model easier to steer with instructions.

It does not

  • Add knowledge the pretraining data did not contain.
  • Make the model truthful in general — it makes it preferred.
  • Guarantee safety against a determined adversary.
  • Remove the annotator's biases from the objective.
§

Preference is not truth. A model trained to be preferred learns what annotators reward, which includes confidence, agreement, and fluency — the same qualities that make a wrong answer persuasive.

Using language models

Decoding, retrieval, evaluation and failure modes.

§

Decoding is a deployment decision, not a model property. Two systems with identical weights behave differently, and an evaluation that does not fix the decoder is not reproducible.

Retrieval: give the model the text it needs

A model cannot recall what it never stored reliably. Retrieval-augmented generation adds a search step: embed the query, find relevant passages, and place them in the context before generating.

RAG changes the failure mode

Instead of hallucinating from memory, the system now fails when retrieval fails — wrong chunk, stale document, or a question that needs synthesis across many passages.

That is an improvement, because retrieval failures are inspectable. You can look at what was retrieved.

§

Evaluate retrieval and generation separately. A system that answers well from bad context has hidden luck; one that answers badly from good context has a generation problem.

Evaluation is the open problem

Why it is hard

  • Open-ended outputs have no single correct answer.
  • Benchmarks saturate, then leak into pretraining data.
  • LLM-as-judge is cheap and biased toward fluent, long, agreeable answers.
  • Aggregate scores hide subgroup failures.

What a defensible evaluation looks like

  • A held-out set you constructed, not one the model was trained on.
  • Task-specific metrics plus a small human audit.
  • Reported per subgroup, not only in aggregate.
  • Failure examples shown, not summarized away.
  • Decoder settings and prompt template reported.
§

Contamination is the default assumption, not the exception. If a benchmark has been public for years, assume the model has seen it unless you can show otherwise.
