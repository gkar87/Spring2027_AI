Networks and backpropagation

Why depth, and how the gradient gets computed.

Why one layer is not enough

A single layer computes a linear function of its input. Composing linear functions gives another linear function, so depth without nonlinearity is wasted.

The XOR problem is the classic demonstration: no line separates (0,1) and (1,0) from (0,0) and (1,1).

XOR(x₁, x₂) = (x₁ ∨ x₂) ∧ ¬(x₁ ∧ x₂)

Forward pass, in the notation we will use all module

z(1) = W(1)x + b(1)
a(1) = σ(z(1))
z(2) = W(2)a(1) + b(2)
ŷ = softmax(z(2))

Each layer is an affine map followed by a pointwise nonlinearity. The nonlinearity is what makes the composition more than a matrix product.

Shapes, because most bugs are shape bugs

  • x ∈ ℝd — the input.
  • W(1) ∈ ℝh×d — one row per hidden unit.
  • a(1) ∈ ℝh — hidden activations.
  • ŷ ∈ ℝk — one score per class.

Activation choices

ReLU is the default because its gradient does not vanish for positive inputs. Sigmoid saturates; tanh saturates less. Softmax is for the output only, when classes are mutually exclusive.

Backpropagation is the chain rule, applied carefully

For a loss L and a two-layer network, the gradient with respect to the first layer's weights is:

∂L/∂W(1) = ((W(2))⊤ ∂L/∂z(2) ⊙ σ′(z(1))) x⊤

Read it right to left: start from the output error, pass it back through the second layer's weights, multiply by the local derivative of the activation, then multiply by the input.

Every layer repeats this pattern. That is the whole algorithm.

Worked scalar example

One hidden unit, w = 2, x = 3, σ = ReLU, output weight v = 4, loss L = ½(ŷ − y)² with y = 10.

z = 2·3 = 6, a = 6, ŷ = 4·6 = 24
∂L/∂ŷ = 24 − 10 = 14
∂L/∂v = 14 · 6 = 84
∂L/∂a = 14 · 4 = 56
∂L/∂w = 56 · 1 · 3 = 168

One gradient step with learning rate 0.01 moves w from 2 to 0.32.

Autodiff exists so you do not do this by hand

A framework records the operations in the forward pass and applies the chain rule in reverse. This is reverse-mode automatic differentiation, and it costs roughly one extra forward pass regardless of how many parameters you have.

That efficiency is why deep learning became practical: the gradient of a billion-parameter model costs about twice a forward pass.

What to know even though the framework does it

  • Gradients accumulate by default; you must zero them each step.
  • In-place operations can break the graph.
  • Detaching a tensor silently stops gradient flow — the classic bug.
  • Numerically unstable losses (log of a softmax) have stable library versions; use them.
§

Always check the gradient numerically once on a tiny model: compare against a finite-difference estimate. It catches sign errors and missing terms in minutes.

The last row is not a hyperparameter problem, and no amount of tuning will fix it. The ability to distinguish "wrong hyperparameter" from "wrong code" is most of the practical skill in this module.

Architectures, regularization and debugging

Convolutions, residuals, and a debugging order that works.

Convolutions: share weights, preserve locality

A convolutional layer slides a small filter across the input, computing the same weighted sum at every position. Three properties follow:

  • Local connectivity — each output depends on a small neighbourhood.
  • Weight sharing — one filter, many positions, far fewer parameters.
  • Translation equivariance — a shifted input produces a shifted feature map.

params = (k · k · Cin + 1) · Cout

Depth needs help: residuals and normalization

Stacking layers should not make a network worse, yet plain deep networks degrade. The fix is to learn a residual:

The identity path gives gradients a direct route to earlier layers, so very deep networks train.

Batch normalization standardizes layer inputs during training, which stabilizes optimization and permits higher learning rates. Layer normalization is its sequence-friendly variant, used in transformers.

What residuals actually buy

With a residual, the network can represent the identity function trivially — so adding a layer cannot hurt in principle. In practice it also improves gradient conditioning, which is the larger effect.

Batch norm caveat

It makes a prediction depend on the other examples in the batch. That is fine for training and a problem for deployment, streaming inference, or very small batches — where layer norm or no normalization is the better choice.

Regularizing a large network

Dropout

Randomly zero units during training so no unit can rely on another. Cheap, effective, and now less common than weight decay in transformers.

Augmentation

Create plausible variations of the input. The most reliable regularizer when it matches the invariances of the task — and harmful when it does not.

Weight decay

Penalize large weights. In modern practice, decoupled weight decay (AdamW) is the default for transformers.

§

Augmentation encodes an assumption: "this transformation should not change the label." Horizontal flips are right for photographs and wrong for digits, where a flipped 6 is not a 6.

Every regularizer is a prior. If the prior is wrong, the regularizer actively hurts — which is why "add augmentation" is not free advice.

The debugging sequence that actually works

  1. 1
    Overfit a single batch

    Train 32 examples to near-zero loss. If that fails, suspect labels or loss.

  2. 2
    Check the labels

    Ten examples with their labels. Label errors commonly cap accuracy.

  3. 3
    Disable the fancy parts

    Remove augmentation, dropout and schedules; train a boring baseline first.

  4. 4
    Verify shapes and gradient flow

    Check shapes once; confirm every parameter gets a non-zero gradient.

  5. 5
    Only then tune

    Learning rate, then batch size, then capacity. In that order.

§

Almost every "model does not learn" problem is a data or code problem, and tuning searches a space that does not contain the bug.

Evaluation in deep learning has its own traps

Traps specific to this setting

  • Test-set reuse — after fifty runs you have effectively trained on it.
  • Best-of-N reporting — reporting the best seed inflates the result.
  • Pretraining contamination — the benchmark was in the pretraining data.
  • Comparison against an untuned baseline — the baseline deserved the same search budget.

The compute-matching rule

If method A got a hundred hyperparameter trials and method B got five, the comparison measures your effort, not the methods.

This is why strong papers report the tuning budget explicitly — and why "our method beats the baseline" is uninformative without it.
