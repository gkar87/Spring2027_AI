Search problems

Five components, two data structures and one generic algorithm.

A search problem has exactly five components

Formal definition

A problem is a tuple (S, A, T, s₀, G, c): a set of states, a set of actions, a transition function, an initial state, a goal test, and a step cost.

A search problem has exactly five components
ComponentQuestion it answersWhere students go wrong
State spaceWhat configuration is the world in?Including information the actions cannot change — needless blow-up.
ActionsWhat can I do from a state?Modelling actions as outcomes ("move to B") instead of attempts ("try to move east").
TransitionWhat happens if I do it?Assuming determinism in a stochastic world.
Goal testAm I done?Testing too late; a cheap test prunes far more than a fast expander saves.
Step costWhat did that cost me?Forgetting that cost can depend on the action, the state, or both.

This formulation assumes the road network is the only relevant fact about the world. That assumption is doing enormous work, and it is worth naming:

  • No traffic, weather, or time of day.
  • No fuel constraint — so the state does not need to include fuel.
  • No uncertainty — every action has one outcome.

Each omission is a modelling claim

Add fuel and the state doubles. Add traffic and the transition becomes stochastic. Both are realistic. Neither is free.

One extra row of tiles. The branching factor barely moved. The depth grew by a factor of 2.4 — and the state count grew by a factor of 5.8 × 10⁷.

§

Exponential growth is not a metaphor. The 15-puzzle is not "harder"; it is a different class of problem, and it is why module 3 exists.

A search tree is not the state graph

The state graph is the problem: nodes are world configurations, edges are actions. The search tree is what the algorithm builds: nodes are paths, and the same world state can appear in many tree nodes.

  • A tree node holds a state, a parent, an action, and a path cost g.
  • The branching factor b counts successors per node; the depth d is the shallowest goal's depth.
  • Repeated states are why graph search keeps an explored set.
§

With b = 10 and d = 12, a tree search visits 10¹² nodes while the reachable state graph may contain a few thousand. Most of that work is repeated.

Two data structures do all the work

Frontier

The set of generated-but-not-yet-expanded nodes. Its discipline is the algorithm.

Frontier
Frontier policyAlgorithm
FIFO queueBreadth-first
LIFO stackDepth-first
Priority: g(n)Uniform cost
Priority: g(n) + h(n)A* (module 3)

Explored set

States already expanded. Its only job is to prevent redundant work, and whether it is safe depends on the algorithm: for uniform cost it is safe, for A* it requires a consistent heuristic.

Storing states costs memory. Re-deriving them costs time. Every practical search engine chooses one and pays for it.

§

Six algorithms in this module are one algorithm with six queue policies. Learning them as six separate procedures is why students forget them.

The generic algorithm, and the one line that varies

function GRAPH-SEARCH(problem, frontier):
  frontier.insert(MAKE-NODE(problem.initial))
  explored = set()

  while frontier not empty:
    node = frontier.remove()          # ← the only line
    if problem.is-goal(node.state):  #    that decides
      return node                    #    the algorithm
    explored.add(node.state)

    for action in problem.actions(node.state):
      child = CHILD-NODE(problem, node, action)
      if child.state not in explored
         and child not in frontier:
        frontier.insert(child)

  return failure

Three details that matter more than they look

  • The goal test happens on removal, not insertion. That makes the algorithm correct for uniform cost, at the cost of possibly expanding extra nodes.
  • The explored check is on states, not nodes. Two nodes can share a state; only the state is duplicated work.
  • Frontier membership checks cost time. A hash set makes them O(1); a list makes them O(n) and quietly destroys your complexity analysis.

Four criteria, and they conflict

Four criteria, and they conflict
CriterionQuestionWhy it is not enough on its own
CompletenessDoes it find a solution whenever one exists?A complete algorithm can still be useless if it takes longer than the universe allows.
OptimalityDoes it find the lowest-cost solution?Only meaningful relative to a cost function; change the cost and the ranking changes.
Time complexityHow many nodes are generated?Counting nodes hides the per-node cost, which varies by orders of magnitude.
Space complexityHow many nodes are held at once?Usually the binding constraint — and the one students forget.
§

These are properties of an algorithm on a problem class, never properties of the algorithm alone. "BFS is optimal" is incomplete without "when every step costs the same."

Uninformed strategies

Breadth, cost, depth and iterative deepening, side by side.

Breadth-first search expands in rings

Expand every node at depth 1, then depth 2, and so on. Because it never expands a deeper node before a shallower one, the first goal it removes is the shallowest — and therefore, if every step costs the same, the cheapest.

Breadth-first search expands in rings
CompleteYes, if b is finite.
OptimalYes, only when all step costs are equal.
TimeO(bd) — it expands the whole level.
SpaceO(bd) — every node of the last level is held.

The cost is not time, it is memory

BFS cannot start the goal level until the previous level is complete, so the frontier is nearly the entire level. That is why it dies at d ≈ 12 in practice.

Uniform-cost search: the cheapest-first frontier

When step costs differ, depth no longer tracks cost. Uniform-cost search orders the frontier by g(n), the cost of the path to that node, and expands the cheapest.

It is Dijkstra's algorithm. It is complete when every step cost exceeds some positive ε — otherwise a zero-cost cycle can be traversed forever.

g(n) = g(parent) + c(parent, n)

Because a node is expanded only when its path is the cheapest known, the explored set is safe here: no cheaper route to that state can appear later.

D is expanded before B, though B is shallower. That is the whole difference from breadth-first.

Depth-first search: the whole answer, one path at a time

DFS expands the most recently generated node. It commits to a path until it dead-ends, then backs up. Its memory cost is small — it holds one path plus the siblings along it.

Depth-first search: the whole answer, one path at a time
CompleteNo, in infinite or cyclic spaces. Yes in finite spaces with a cycle check.
OptimalNo. It returns the first solution it stumbles into.
TimeO(bm) where m is the maximum depth.
SpaceO(bm) — linear, and that is the entire appeal.
§

DFS is the only uninformed method whose memory grows linearly with depth. A long dead-end branch absorbs all its time, and on an infinite tree there is always another node to descend into.

Iterative deepening: DFS's memory, BFS's answers

Run depth-limited search with limit 0, then 1, then 2, and so on until a goal is found. It sounds wasteful — it re-expands the top levels many times.

N(IDS) = (d+1)·1 + d·b + (d−1)·b² + … + bd ≈ bd·b/(b−1)

For b = 10 the overhead factor is about 1.11. An 11% increase in time buys a memory reduction from O(bd) to O(bd). That is the best trade in classical AI.

IDS is complete, optimal for uniform step cost, O(bd) time, and O(bd) space. It is the default uninformed choice.

Two different walls

Time grows by a factor of 10 per level; memory grows by the same factor. But memory runs out first in practice, because the machine has less of it and because the frontier must be randomly accessible, which rules out streaming it to disk.

This table is the honest answer to "why not just search harder?" At d = 12, breadth-first search needs more memory than exists in a small data center — for a problem with ten actions per state.

Beyond the basics

Searching from both ends, and when the explored set is safe.

Bidirectional search halves the exponent

Search forward from the start and backward from the goal, and stop when the two frontiers meet. If both searches go to depth d/2, the cost is O(bd/2) instead of O(bd).

For b = 10 and d = 12, that is 10⁶ instead of 10¹² — a factor of a million.

The catch is the backward step

You must be able to generate predecessors. For "drive to Bucharest" that is easy. For "win this chess position" it is not defined: many positions can precede a given one.

Where the explored set is safe — and where it is not

Safe: uniform cost

If a node is expanded with cost g, every other frontier node has cost ≥ g. Any alternative path to that state would have to pass through the frontier, so it would cost at least as much. Discarding the state cannot lose a cheaper path.

Not automatically safe: A*

With an inconsistent heuristic, A* can reach a state by an expensive path, expand it, and only later find a cheaper route. If the explored set blocked re-expansion, the cheaper route would be lost and the answer would be wrong.

Module 3 fixes this with consistency, which is exactly the condition that restores the argument.

§

An optimization is only correct relative to a proof. The explored set is an optimization. Here is its proof, and here is the assumption it needs.

Key takeaways

  1. 1
    The frontier policy is the algorithm.

    Queue, stack, or priority queue — six algorithms, one loop.

  2. 2
    Tree nodes are paths; states are configurations.

    Confusing them is the origin of both duplicate work and incorrect explored sets.

  3. 3
    Optimality always carries a condition.

    "BFS is optimal" means "when step costs are equal."

  4. 4
    Memory is the binding constraint.

    1.1 PB at depth 12 with ten actions per state.

  5. 5
    Iterative deepening is the sensible default.

    BFS-quality answers at DFS-quality memory, for about 11% extra time.
