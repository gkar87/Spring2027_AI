Constraint satisfaction

Change the representation and the algorithm changes with it.

The representation changes the algorithm

In a search problem, a state is a complete world configuration and an action changes it. In a CSP, a state is a partial assignment and an action assigns a value to one variable.

  • The goal test is "all variables assigned and no constraint violated."
  • The path does not matter — only the final assignment does.
  • Therefore the order of assignment is irrelevant, and the branching factor collapses.

Commutativity is the whole advantage

Assigning Missouri first and Kansas second produces the same result as the reverse. A search algorithm that treats them as different paths explores n! orderings of the same assignment, for n variables.

For 25 variables that is 1.5 × 10²⁵ duplicate paths — thrown away by changing the representation, not the hardware.

§

This is the same lesson as module 1: formulation is the decisive step. Here it is worth a factor of 10²⁵.

Formal definition

Constraint satisfaction problem

A set of variables X = {X₁, …, Xn}, a domain Di for each, and a set of constraints C. A solution is a complete assignment satisfying every constraint.

Constraint kinds

  • Unary — restricts one variable (e.g. room capacity ≥ enrollment).
  • Binary — relates two (e.g. X ≠ Y).
  • Global — relates any number; AllDifferent is the workhorse.
  • Soft — preferred but violable, which turns the problem into optimization.

What counts as a solution

A consistent assignment violates no constraint. A complete assignment covers every variable. A solution is both.

Many real problems have no solution at all, and the useful output is then a minimal explanation of why — which is a different algorithm.

The constraint graph makes structure visible

Draw one node per variable and one edge per binary constraint. The graph's shape tells you how hard the instance is, and it is the only picture that makes the algorithms in this module intuitive.

  • A tree can be solved in time linear in the number of variables.
  • A dense graph is where backtracking struggles.
  • Independent components can be solved separately and combined.

Search with inference

Backtracking, forward checking, arc consistency and ordering.

Backtracking search is depth-first search over assignments

function BACKTRACK(assignment, csp):
  if assignment is complete:
    return assignment          # solution

  var = SELECT-UNASSIGNED-VAR(csp, assignment)
  for value in ORDER-DOMAIN-VALUES(var, assignment):
    if value is consistent with assignment:
      assignment[var] = value
      result = BACKTRACK(assignment, csp)
      if result is not failure:
        return result
      del assignment[var]        # undo

  return failure

The two capitalised lines are the entire research area. Which variable next, and which value next? Everything else is bookkeeping.

Three optional improvements, in increasing order of power:

  1. Forward checking — prune domains of neighbours when you assign.
  2. Constraint propagation — enforce arc consistency after each assignment.
  3. Intelligent backtracking — jump back to the variable that caused the conflict.

Forward checking: look one step ahead

When you assign X = v, remove from each unassigned neighbour's domain every value inconsistent with v. If any domain becomes empty, backtrack immediately.

Worked example — colouring with three colours

Assign A = red: B, C and D lose red. Assign B = green: C loses green, so C = blue is forced, and E loses green. Assign D = blue: E loses blue, so E = red is forced. Now try F = red: E's domain becomes empty, so backtrack before expanding anything below.

What forward checking achieves

It detects failure as soon as a domain empties, rather than after assigning every remaining variable and discovering the conflict at the leaf.

What it does not achieve

It does not reason between two unassigned variables. After D = blue, C can only be blue and E can only be red, which leaves F one safe value. Forward checking does not work that out; it waits until F = red fails.

That gap is exactly what arc consistency closes.

Arc consistency: every value must have a partner

Arc consistency

A binary constraint between X and Y is consistent (the arc X → Y is satisfied) if for every value in DX there exists some value in DY that satisfies the constraint.

Note the direction. Arc consistency is checked per directed arc, and X → Y can hold while Y → X fails.

Enforcing it means deleting values that have no support. Deleting a value can break a neighbouring arc, so the process must repeat to a fixed point.

What it guarantees, and what it does not

  • Guarantees: no domain is empty, and every remaining value can be extended one step.
  • Does not guarantee: a solution exists. A network can be arc-consistent and still unsatisfiable.
§

Arc consistency is sound pruning, not a decision procedure. On tree-structured graphs it becomes one, which is why slide 18 matters.

The AC-3 algorithm

function AC-3(csp):
  queue = all arcs in csp  # both directions

  while queue not empty:
    (X, Y) = queue.pop()
    if REVISE(csp, X, Y):  # domain of X changed
      if D[X] is empty:
        return false       # inconsistent
      for Z in neighbours(X) − {Y}:
        queue.push((Z, X)) # recheck arcs into X

  return true

Trace on the colouring example

State after A = red, B = green, D = blue: C {blue}, E {red}, F {red, green, blue}. REVISE(X, Y) prunes X.
StepArcEffect
1C → ANo change (blue is supported)
2E → DNo change (red is supported)
3F → CF loses blue → F {red, green}
4F → EF loses red → F {green}
5C → F, E → FRe-queued; no change → return true

Propagation alone forces F = green, so the F = red dead end from forward checking never happens. That is the difference between checking and reasoning.

O(e · d³) e arcs, domain size d. Each arc may be revised at most d times, each revision costs d².

Variable ordering: fail first, fail fast

Minimum remaining values (MRV)

Choose the unassigned variable with the fewest legal values left. Also called the "most constrained variable" heuristic.

The reasoning is a chess principle: if a branch is going to fail, you want to know now, while the tree above it is small. MRV picks the variable most likely to fail immediately.

Degree heuristic

Break ties by choosing the variable involved in the most constraints with other unassigned variables. It is a tie-breaker, not a primary rule.

Value ordering: succeed first

Least constraining value (LCV)

Among the values for the chosen variable, try first the one that rules out the fewest values in neighbouring domains.

MRV asks "which variable is most likely to fail?" LCV asks "which value is least likely to cause failure?" The first reduces the tree; the second hopes to find a solution on the first branch, which matters when you need only one solution.

If you needed all solutions, LCV would be pointless: you must explore everything anyway.

The phase transition

Random CSPs are easy when constraints are sparse (many solutions) and easy when they are dense (fail fast), and hardest near the ratio where satisfiability flips.

That peak is where benchmark instances live, and it is why published node counts differ by orders of magnitude between papers that look similar.

When you read a solver benchmark, ask where on this curve the instances sit. A method that wins at the peak may lose everywhere else.

Local search and structure

Repair a complete answer, and use the shape of the problem.

Local search: stop building a tree, start repairing an answer

Keep a complete assignment and change one variable at a time to reduce the number of violated constraints. No backtracking, no tree, constant memory.

Min-conflicts on 8-queens

Place eight queens randomly. Repeatedly pick a queen in conflict and move it to the row in its column that minimizes conflicts.

Average work: about 50 steps, for a space of 8⁸ = 16.7 million

The same method solves million-queens instances in about the same number of steps. That is not a constant-factor improvement; it is a different scaling law.

Why it works so well on n-queens

A random complete assignment has very few conflicts, and each move fixes local trouble. The solution density is high enough that hill climbing finds one quickly.

Why it fails elsewhere

If solutions are rare, or the constraints are tight enough that any single move creates new conflicts, min-conflicts wanders. It also cannot prove unsatisfiability — it can only fail to find a solution.

Hill climbing, and the landscape it climbs

Hill climbing moves to the best neighbour; it stops at a local maximum. Three standard escapes:

  • Random restart — begin again elsewhere; effective when restarts are cheap.
  • Stochastic hill climbing — pick randomly among uphill moves, biased by steepness.
  • Simulated annealing — accept downhill moves with probability e−Δ/T, lowering T over time.
P(accept) = e−ΔE / T

Structure: the only reliable way to make hard problems easy

Independent subproblems

If the constraint graph splits into components with no edges between them, solve each separately and combine. A problem that looks like O(dn) becomes O(dc) per component of size c.

Tasmania and the Australian mainland are the textbook example; the UCM example is a set of courses that share no students.

Tree-structured constraints

If the constraint graph is a tree, arc consistency is enough: run AC-3, then do a linear pass assigning values that keep each arc satisfied. Time is O(nd²), with no backtracking at all.

Cutset conditioning

For a graph that is nearly a tree, assign a small set of variables, simplify to a tree, and solve the tree. Exponential only in the cutset size.

§

Find the structure before you find a faster solver. A factor of d from better ordering is nice; a factor of d(n−c) from decomposition is a different problem.

Key takeaways

  1. 1
    Representation beats search.

    Commutativity removes n! duplicate orders before any optimization.

  2. 2
    Prune with reasoning, not with luck.

    Forward checking looks one step ahead; arc consistency looks at every remaining value.

  3. 3
    Arc consistency is sound but incomplete.

    It prunes, it does not decide — except on trees.

  4. 4
    MRV for variables, LCV for values.

    Fail first for the tree; succeed first for a single solution.

  5. 5
    Local search is a different scaling law.

    Fifty steps for 8-queens, and the same fifty for a million — when it works.
