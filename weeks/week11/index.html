The learning problem

What we minimize, and what we actually want.

The learning problem

Given examples drawn from an unknown distribution, choose a hypothesis h from a hypothesis class H that predicts well on unseen examples from the same distribution.

h* = argminh∈H E(x,y)~D[ L(h(x), y) ]

The expectation is over the true distribution, which we do not have. So we minimize the average over the training set instead — empirical risk.

Training loss is not the objective

Minimizing training error is trivially solvable: memorize the training set. A lookup table achieves zero training loss and learns nothing.

What we want is low generalization error — performance on data we have not seen. The gap between the two is the entire subject.

generalization error = training error + generalization gap

The three sources of gap

  1. Variance — the model fits noise specific to this sample.
  2. Distribution shift — test data is not drawn from the same distribution.
  3. Leakage — information from the test set reached training, so the estimate is optimistic.

The first is a modelling problem. The second is a deployment problem. The third is a methodology error, and it is the most common in student projects.

Bias, variance, and the shape of the error curve

E[(y − ĥ(x))²] = σ² + Bias(ĥ)² + Var(ĥ)

Irreducible noise, plus systematic error, plus sensitivity to the particular training sample. As model complexity rises, bias falls and variance rises.

  • High bias — training and test error both high, and close together.
  • High variance — training error low, test error much higher.

Regularization: constrain the hypothesis class

Add a penalty for complexity to the objective. This is equivalent to restricting the hypothesis class, which reduces variance at the cost of some bias.

L = training loss + λ · R(θ)

λ is a real trade-off

Too small and you overfit; too large and you underfit. It must be chosen on validation data, never on the test set — and reporting the test score after tuning λ on it makes the score meaningless.

§

Every hyperparameter you tune on a set consumes some of its value as an unbiased estimate. Tune on validation, report on test, once.

Cross-validation, and the leaks that ruin it

Split the data into k folds; train on k−1 and validate on the held-out fold; average. This gives a less noisy estimate than a single split, which matters when data is limited.

For time series, use a forward-chaining split: never train on the future to predict the past.

§

If a result looks surprisingly good, suspect leakage before celebrating.

Four leaks that appear constantly

  • Preprocessing before splitting — normalizing with the full dataset's mean leaks test statistics.
  • Feature selection on all data — choosing features using test labels inflates performance.
  • Duplicate rows across splits — near-identical examples make the test set a memory test.
  • Group leakage — two images of the same patient in train and test.

Measuring what matters

Metrics, calibration and the decision behind them.

Accuracy is a decision, not a metric

With 1% positives, a classifier that always predicts "negative" is 99% accurate and worthless. Accuracy implicitly weights every error equally, which is almost never what the deployment wants.

precision = TP / (TP + FP)
recall = TP / (TP + FN)
F₁ = 2 · precision · recall / (precision + recall)

Choose by cost of error

  • Screening — a missed case is expensive, so favour recall and accept false alarms.
  • Enforcement — a false accusation is expensive, so favour precision.
  • Ranking — use precision at k, or mean average precision.

There is no metric that is right in general. There is a metric that matches the consequence of being wrong, and naming that consequence is part of the modelling.

Calibration is separate from discrimination

A model can rank cases perfectly and still report probabilities that are wrong. Ranking is discrimination; the meaning of the number is calibration.

If a model says 0.9 for a hundred cases, a calibrated model has about ninety positives among them. A well-ranked, badly calibrated model might have fifty.

ECE = Σbins (nbin/N) · |accuracy − confidence|

Why it matters for decisions

Any decision that weighs a probability against a cost needs calibration. A triage system that says "0.8 risk" will be used as if 0.8 means 0.8.

Fixes: Platt scaling, isotonic regression, temperature scaling. All are post-hoc and cheap — and all require held-out data.

§

ROC curves are insensitive to calibration because they use only ranking. If calibration matters, report a reliability diagram too.

Three classic models

Naive Bayes, logistic regression and decision trees.

Naive Bayes, worked

Assume features are conditionally independent given the class. Estimate each conditional probability by counting, add smoothing, and multiply.

Spam filtering

P(spam) = 0.4. The word "free" appears in 60% of spam and 5% of ham. A message contains "free".

P(spam | free) ∝ 0.4 × 0.6 = 0.24
P(ham | free) ∝ 0.6 × 0.05 = 0.03

Normalized: 0.89 spam, 0.11 ham.

Two things this example teaches

  • The prior matters: with P(spam) = 0.01 the same evidence gives a much lower posterior.
  • The independence assumption is false — words correlate — and the classifier still works.

Why it still works

It needs the ranking to be right, not the probabilities. Overconfident scores that preserve order still classify correctly — which is exactly the discrimination versus calibration distinction.

Logistic regression: a linear model with a probability output

P(y=1 | x) = σ(w·x + b) = 1 / (1 + e−(w·x+b))

The decision boundary is linear; the output is a probability. Trained by minimizing log loss, which is the negative log-likelihood:

L = −Σ [ y log p + (1−y) log(1−p) ]

Why it is still the baseline to beat

  • It is convex, so training is reliable and fast.
  • Coefficients are interpretable as log-odds ratios.
  • It is well calibrated by construction on the training distribution.
  • It fails in an informative way: if a linear model matches your neural network, the problem is not the model.

A project that beats logistic regression by 0.3% has not shown that deep learning was needed. It has shown that 0.3% is within noise.

Decision trees, and what entropy buys

Split on the feature that most reduces label impurity. With entropy as the impurity measure, the gain is:

Gain = H(S) − Σv (|Sv|/|S|) · H(Sv)
H(S) = −Σc pc log₂ pc

Properties worth knowing

  • Trees capture interactions automatically — no feature crosses needed.
  • They are unstable: a small data change can produce a different tree.
  • Deep trees memorize, so depth and leaf size are the regularization.
  • Ensembles (random forests, gradient boosting) fix the instability and remain the strongest tabular baseline.
§

Unstable does not mean inaccurate. It means the explanation changes, which matters when the tree is the deliverable rather than the prediction.

A reporting checklist you will be graded against

Must be present

  • The split, and how it was made.
  • The metric, and why that metric.
  • At least one trivial baseline.
  • Mean and spread over at least five seeds or folds.
  • Every hyperparameter tuned, and on what data.

Immediately disqualifying

  • Test accuracy reported after tuning on the test set.
  • A single run, presented as the result.
  • No baseline, so the number has no scale.
  • Accuracy on a 2% positive class.
  • "We used a 70/30 split" with no explanation of how leakage was prevented.

This checklist is not bureaucratic. Every item on it corresponds to a way published results have been wrong, and most of them have been wrong in this decade.
