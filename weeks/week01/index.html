What counts as intelligent

Four definitions, and the one this course uses: rational agents.

Four definitions, four different research programmes

The two axes are thought versus behaviour and human standard versus rational standard. Russell and Norvig, §1.1.
Human-centred Rationalist
Thinking Thinking humanly. Model cognition itself; validate against psychology and neuroscience. Thinking rationally. Laws of thought; logic and probability as the standard.
Acting Acting humanly. The Turing test; indistinguishable behaviour is the goal. Acting rationally. Maximize expected performance in an environment.

Each cell buys something and pays for something. The Turing test avoids defining consciousness but measures imitation, not competence. The laws-of-thought approach gives proofs but assumes the world can be written down completely.

§

This course takes the acting rationally view. Not because the others are wrong, but because it is the only one that produces a specification you can test.

Rationality is a relationship, not a property

Rational agent

For each possible percept sequence, an agent should select an action that is expected to maximize its performance measure, given the evidence provided by the percept sequence and whatever built-in knowledge it has.

f : P* → A

An agent is a function from percept histories to actions. That is the whole formal object. Everything else — neural networks, planners, lookup tables — is an implementation of that function.

Three words doing the work

  • Expected — rationality is about what the agent knows, not what turns out to be true. A rational agent is not omniscient.
  • Performance measure — defined by the designer, outside the agent.
  • Percept sequence — not the current percept alone. Memory is part of the input.

The classic counterexample

A vacuum agent that moves at random may clean a room by luck. It performed well; it did not act rationally. Benchmarks reward outcomes, so we must reason about the policy, not just the score.

An agent is a program running on an architecture

The architecture is the machinery: sensors, actuators, and the computing substrate. The program is the function f. Keeping them separate is what lets the same algorithm run on a robot, a web service, or a simulated grid.

  • Percept — the content the agent receives at one instant.
  • Percept sequence — the complete history, which is the true input to f.
  • Action — what the agent emits; the environment decides the consequence.
§

The agent never sees the world. It sees its sensors. Most AI failures are failures to remember this.

PEAS: describe the task before you write any code

Performance measure, Environment, Actuators, Sensors. Four columns that force you to name what "good" means before you fall in love with an algorithm.

Worked example: an academic-advising assistant for a graduate program.
Performance Environment Actuators Sensors
Student reaches graduation on time; fewer unnecessary credit hours; low advisor workload Course catalog, prerequisites, term offerings, student records, program rules Recommended plan, warning message, escalation to a human advisor Transcript, current enrollment, declared program, deadline calendar

The performance measure is a design decision

"Students graduate on time" and "students take the courses they are interested in" are different objectives that produce different advising. Neither is discoverable from the data; both come from a human.

Write PEAS first, and disagreements surface early

Most failed AI projects did not fail at modelling. They failed because two stakeholders meant different things by "good" and nobody wrote it down.

Six properties, and what each one costs you

Six properties, and what each one costs you
PropertyIf the hard option holds…
Fully observable vs partiallyYou must maintain beliefs over hidden state — module 10's particle filters exist for this reason.
Deterministic vs stochasticYou need probabilities and expected values, not just plans — modules 6 through 9.
Episodic vs sequentialCurrent decisions change future options; you cannot optimize one step at a time.
Static vs dynamicThe world moves while you think; a plan can be stale before it is executed.
Discrete vs continuousEnumeration fails; you need function approximation or search over continuous space.

§

These are not six independent yes/no questions. The hardest realistic combination — partially observable, stochastic, sequential, dynamic, continuous, unknown — is the one an autonomous agent in the physical world actually faces.

Five agent designs

Each one adds a single capability, and each fails in its own way.

Five designs, each adding one capability

  1. 1
    Simple reflex

    Condition–action rules on the current percept. No memory, no model.

  2. 2
    Model-based reflex

    Keeps internal state to track the part of the world it cannot see.

  3. 3
    Goal-based

    Adds a target and searches for action sequences that reach it.

  4. 4
    Utility-based

    Adds preferences, so competing goals can be traded off.

  5. 5
    Learning

    Improves all of the above from experience, guided by a critic.

A reflex agent, and the exact moment it fails

# Rule: if the current square is dirty,
# clean it; otherwise move to the other square.
def reflex_agent(percept):
    location, status = percept
    if status == "Dirty":
        return "Suck"
    elif location == "A":
        return "Right"
    else:
        return "Left"

It works — until the world is bigger than its rules

In a two-square world this agent is optimal. Move it to three squares and it oscillates forever between two clean rooms, never reaching the third. The code did not get worse; the environment outgrew the representation.

This is the pattern to watch for all term: a method fails not where it was tested, but one assumption away from where it was tested.

Model-based agents remember what they cannot see

A model-based agent keeps two things: a transition model ("if I move right, where do I end up?") and a sensor model ("if the world is like this, what would I perceive?"). Together they let the agent maintain internal state.

  • The state is a belief, not a fact. It can be wrong.
  • Updating it is inference — module 9 and 10 will make this precise.
  • Memory is not free: the state space of beliefs is much larger than the state space of the world.
§

An agent that remembers is an agent that can be mistaken about the past.

Goals say "reach it"; utilities say "how much do I want it"

Goal-based

The agent searches for a sequence of actions that reaches a goal state. Its output is a plan. Its weakness is that all goal states are equally good, so it cannot choose between two plans that both succeed.

plan = [a₁, a₂, …, aₙ] such that result(s₀, plan) ⊨ goal

Utility-based

The agent maximizes expected utility, so it can compare outcomes with different likelihoods and different values. This is what lets it accept a risk, or refuse one.

a* = argmaxa Σs′ P(s′ | s, a) · U(s′)

§

A goal-based agent that plans a route with a 40% chance of arrival is not wrong — it is answering a different question than you asked. Utility is how you ask the question you actually meant.

Learning agents trade correctness for improvement

Four components: the performance element acts, the critic judges the action against a fixed performance standard, the learning element changes the performance element, and the problem generator proposes exploratory actions.

The critic is the load-bearing part. It must be fixed and external, because an agent that can edit its own success criterion will always succeed.

This is where the course turns

Modules 1–6 build agents that are given a model. Modules 7 onward build agents that must estimate it — and the critic becomes a reward signal, a loss function, or a preference dataset.

Formulating problems, and what is still open

Where the real difficulty sits before any algorithm runs.

Formulation is where the real difficulty lives

The 8-puzzle: a 3×3 grid with eight numbered tiles and one blank. Slide a tile into the blank; reach the ordered arrangement.

The lesson generalizes

Choosing what a state contains is a modelling decision with a computational price. Too little, and the agent cannot distinguish situations that need different actions — the Markov property fails. Too much, and the state space becomes unsearchable.

Every algorithm in modules 2 through 7 is downstream of this choice.

§

181,440 is small. 10¹³ is not. The same puzzle family, the same rules, and a completely different algorithmic situation — because of one number.

Six shifts, and what each one actually changed

Two things to notice. First, the field has repeatedly rediscovered that scale changes which methods are correct, not just which are fast. Second, each shift kept the previous mathematics: A* from 1968 still runs inside modern game engines and robot planners.

What is genuinely unsolved

Generalization outside the distribution

A model that is 95% accurate on its test set can collapse on the same task in a different hospital, dialect, or camera. We can measure this; we cannot yet guarantee against it.

Grounding and reference

A language model manipulates symbols that co-occur with the world. Whether that constitutes referring to the world is contested — and it matters for whether we can trust a system's claims about it.

Evaluation

Benchmarks saturate, then leak into training data. We are better at building systems than at knowing whether they work, and the gap is now the binding constraint on deployment.

Alignment and control

Specifying what we want, in a form an optimizer cannot satisfy by exploiting the specification rather than the intent, remains open. Modules 7 and 13 show the mechanism; module 15 shows the stakes.

§

You are entering a field where the engineering is ahead of the science. That is uncomfortable and it is also the opportunity.
