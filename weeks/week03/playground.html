How to use this page

  • Choose an algorithm and press Step to expand one node at a time, or Run to the goal. Each square shows the order in which it was expanded; dashed squares are waiting in the frontier.
  • Each exercise has a Check answer button (or press Enter in a box). Numbers may be rounded to three decimal places or written as a fraction. Work them on paper first: the exams ask the same kind of question with no explorer to help.
  • Solved exercises are remembered in this browser only. Nothing here is graded.

The search explorer

A grid from start S (square A1) to goal G (square I5). Moves go up, right, down or left, one square at a time. A move into an ordinary square costs 1; a move into mud costs 3; black squares are walls. Every algorithm here is graph search: it never expands a square twice, it tests for the goal when it expands a square, it generates neighbours in the order up, right, down, left, and it breaks ties first in, first out.

Note for Lab 1: Manhattan distance is admissible here because moves are four-way. Lab 1's grid is eight-way, with diagonal moves costing 1.5, and there Manhattan can overestimate, so it is not admissible; octile distance is.

More examples to try

Three more grids for the same five algorithms. Run each algorithm on each grid and compare the line under the grid: nodes expanded and path cost.

Mud between start and goal

The straight row to G is all mud. Run breadth-first search, then uniform-cost search.

What to notice

Breadth-first search takes the 9 moves straight through the mud, cost 21. Uniform-cost search and A* go around through the bottom row: 15 moves, cost 15. Greedy and the doubled heuristic take the mud, like BFS, because they ignore what the path costs.

A maze that fools greedy search

Greedy best-first heads for the square that looks closest. Compare it with A*.

What to notice

Greedy expands 36 squares and returns a path of cost 14; A* expands 21 and returns the cheapest path, cost 12. Squares that look close to G can be far from it by the corridors.

An open field

No walls, no mud. Compare uniform-cost search with A*.

What to notice

A* expands all 70 squares, as many as uniform cost. Every square on a shortest route has the same f = g + h = 15, and ties are broken first in, first out, so the heuristic cannot single out a route. Greedy expands only 16. A good heuristic helps most when it separates promising squares from the rest.

Exercises

Use the explorer for exercises 1, 2, 4 and 5; work exercises 3 and 6 by reasoning.

Exercise 1

Run breadth-first search to the goal. How many nodes does it expand, counting the goal, and what is the cost of the path it returns?

Hint

Choose Breadth-first search and press Run to the goal; read the line under the grid. Then count why the cost is more than the number of moves.

Show a solution

40 nodes; the path has 12 moves, but three of them enter mud, which costs 3, so the cost is 9 + 3 × 3 = 18. BFS minimizes moves, not cost.

Exercise 2

Now uniform-cost search. How many nodes does it expand, and what is the cost of its path?

Hint

UCS pops the node with the lowest path cost so far, so it walks around the mud.

Show a solution

35 nodes, cost 14: a 14-move path with no mud. It is optimal, because step costs are positive and UCS expands nodes in order of cost.

Exercise 3

What is the Manhattan-distance heuristic h at the start square A1? The goal is I5.

Hint

Count columns from A to I and rows from 1 to 5.

Show a solution

8 columns + 4 rows = 12. The true cost from A1 is 14, so h does not overestimate here, as admissibility requires.

Exercise 4

Run A* with Manhattan distance. How many nodes does it expand?

Hint

Same path as UCS; compare the number expanded.

Show a solution

28, against 35 for UCS: the heuristic steers the search toward the goal and it still returns the optimal cost 14, because Manhattan distance is admissible and consistent on a four-way grid whose steps cost at least 1.

Exercise 5

Run A* with twice the Manhattan distance. What path cost does it return?

Hint

Doubling h makes it overestimate. Compare with exercise 2.

Show a solution

18, through the mud, after expanding only 19 nodes. With h multiplied by w = 2 the cost is guaranteed to be at most 2 × 14 = 28, but it is no longer optimal.

Exercise 6

Which algorithms are guaranteed to return the cheapest path on every grid like this one?

Hint

Think about which ones look at path cost, and which heuristics never overestimate.

Show a solution

UCS and A* with an admissible heuristic. BFS is optimal only when every step costs the same; greedy ignores the cost so far; the doubled heuristic can overestimate.
