Two questions recur on the midterm: is this heuristic admissible, and why does that matter here? Answer both or the argument is incomplete.

Why heuristics

Uninformed search cannot be rescued by faster code.

Why uninformed search cannot be rescued by better hardware

Breadth-first search expands nodes in order of depth. It has no way to prefer a node that looks promising over one that does not, because it has no notion of promising at all.

Consider route finding on a road network with a million intersections. BFS expands in rings of equal road distance, so it explores equally in every direction — including directly away from the destination.

The wasted work is directional

In a roughly circular search, BFS expands the full disc of radius d, but only a narrow wedge points toward the goal. The fraction of wasted expansion grows with d, so more computing power buys you a slightly larger disc and the same proportional waste.

The fix is information, not speed.

§

A heuristic is extra knowledge about the problem, supplied by a human or learned from data. Every practical search system has one; the only question is whether it is stated honestly.

A heuristic estimates the distance that remains

Heuristic function

h(n) estimates the cost of the cheapest path from the state at node n to a goal state. It is a property of the problem, not of the algorithm.

Where heuristics come from

  • Relaxation — solve an easier version of the problem and use its exact cost.
  • Landmarks — precompute true distances to a few reference points and apply the triangle inequality.
  • Pattern databases — solve every instance of a subproblem exactly, once.
  • Learning — fit a model to observed costs; admissible only if you can bound the error.

What it must satisfy

For A* to be optimal, h must never overestimate. That single condition, admissibility, is the subject of the next three slides.

0 ≤ h(n) ≤ h*(n)

h* is the true remaining cost. h = 0 gives uniform-cost search; perfect h = h* goes straight to the goal.

Greedy best-first search: trust the estimate completely

Order the frontier by h(n) alone and expand the node that looks closest to the goal. It is fast, and it is not optimal, because it ignores what the path has already cost.

Worked example — Arad to Bucharest

Straight-line distances make Sibiu (253 km) look better than Zerind (374) or Timisoara (329), so greedy goes Arad → Sibiu → Fagaras → Bucharest.

140 + 99 + 211 = 450 km

The optimal route is Arad → Sibiu → Rimnicu Vilcea → Pitesti → Bucharest:

140 + 80 + 97 + 101 = 418 km

Why it failed

Fagaras is genuinely close to Bucharest as the crow flies, but the road from Fagaras to Bucharest is long. Greedy never asked what reaching Fagaras had already cost.

Greedy is not complete in infinite spaces, and it is not optimal in general. Its complexity is O(bm) in the worst case, though it is often fast in practice.

A* and its guarantees

Cost so far plus cost to go, and the two conditions that make it optimal.

A*: cost so far plus cost to go

A* orders the frontier by f(n) = g(n) + h(n): the cost already paid plus the estimated cost remaining.

f(n) = g(n) + h(n) g is exact and known; h is estimated and must not overestimate.

One line changes and the algorithm becomes both complete and optimal, under one condition on h. That is the most favourable cost-to-benefit ratio in this course.

Admissibility is exactly the condition for optimality

Admissible

h never overestimates the true cost to the nearest goal: h(n) ≤ h*(n) for every node n.

Theorem. A* with tree search and an admissible heuristic returns an optimal solution.

  1. Suppose A* returns goal G₂ with cost g(G₂) > C*.
  2. An optimal solution exists; let n be an unexpanded frontier node on it.
  3. By admissibility, f(n) = g(n) + h(n) ≤ C*.
  4. A* expanded G₂ first, so f(G₂) ≤ f(n) ≤ C*.
  5. But f(G₂) = g(G₂) > C* — contradiction.

Why step 2 is always available

If A* has not yet found the optimum, some node on the optimal path is still sitting in the frontier. That node's f value is a lower bound on C*, so A* cannot pass it by.

§

The proof is a contradiction about an ordering. If you remember only that, you can reconstruct the rest.

Note the two hypotheses: admissibility, and tree search. Relaxing either breaks the conclusion — which is the next slide.

Consistency: the stronger condition that fixes graph search

Consistent (monotone)

For every node n and successor n′ reached by action a with cost c:

h(n) ≤ c(n, a, n′) + h(n′)

This is the triangle inequality along every edge.

Consistency implies admissibility: by induction along a path to a goal, the telescoping sum gives h(n) ≤ h*(n). The converse is false — some admissible heuristics are inconsistent.

What consistency buys

Along any path, f is non-decreasing. So when A* expands a node, it has already found the cheapest route to that state — and the explored set is safe. Without consistency the explored set can block a cheaper path, and A* with a graph-search explored set is no longer optimal.

§

Admissible gives you optimality on a tree. Consistent gives you optimality with a hash set. The second is what you actually need in practice.

Practical fix if you must use an inconsistent heuristic: allow re-expansion when a cheaper path is found (closed-list reopening). Correct, but slower.

The instructive detail

Fagaras (415) is expanded before Pitesti (417) and puts Bucharest on the frontier at 450. A* stops only when it removes the goal, and by then Pitesti has found the 418 route. The expansion order is not the solution path.

What this teaches

A* never expands a node whose f exceeds the optimal cost. The optimal cost is 418, and every expanded node has f ≤ 418. That is the theorem from slide 9 happening on a real graph.

Designing heuristics, and trading optimality

Relaxations, dominance, pattern databases and bounded search.

Designing a heuristic by relaxing the problem

Remove a constraint from the problem. The optimal cost of the relaxed problem is never more than the optimal cost of the real one — so it is an admissible heuristic.

8-puzzle relaxations and the heuristics they produce.
RelaxationResulting h
A tile can move anywhereNumber of misplaced tiles
A tile can move to any adjacent squareSum of Manhattan distances
Tiles can overlapPattern database over a tile subset

Admissible is a floor; dominance decides which heuristic wins

For the 8-puzzle, both heuristics are admissible. But Manhattan distance is always at least as large as the misplaced-tile count, and sometimes larger.

Dominance

h₂ dominates h₁ if h₂(n) ≥ h₁(n) for all n, and both are admissible. A* with h₂ expands no more nodes than A* with h₁.

A larger admissible heuristic is a tighter lower bound, so fewer nodes satisfy f ≤ C* and fewer get expanded.

§

You can always combine admissible heuristics by taking the maximum — it stays admissible and dominates each input. h(n) = max(h₁, h₂).

Pattern databases: solving a subproblem exactly, once

Choose a subset of the puzzle — say tiles 1 through 8 in the 15-puzzle. Ignore the rest. Run a backward breadth-first search from the goal over every arrangement of that subset, and store the true distance for each.

The stored distance is a lower bound on the real cost, because the ignored tiles can only add moves, never remove them.

h(n) = sum over disjoint patterns of their exact costs

With several disjoint pattern databases you may add their costs (each move affects only one pattern); with overlapping ones you must take the maximum, because they can count the same move twice.

Why this is the standard technique

  • The table is computed once, offline, and reused for every instance.
  • It is exact for the subproblem, so it is admissible by construction.
  • It scales to the 24-puzzle, where it was the difference between solvable and not.

The trade is memory for search: a pattern database is a cache of solved subproblems. That is the same trade as memoization, applied to a search.

When optimal is too slow: bounded suboptimality

Weighted A* orders the frontier by f = g + w·h with w > 1. It behaves greedily: it reaches a solution much faster and accepts a solution that may be worse.

The guarantee is still useful. Weighted A* returns a solution costing at most w times optimal.

C ≤ w · C* Requires h admissible. w = 1 is ordinary A*; w = ∞ is greedy best-first.

The engineering question

For a delivery router, a route 5% longer that is computed in 40 ms may be worth far more than an optimal route computed in 4 seconds. Bounded suboptimality makes that trade explicit instead of accidental.

Anytime behaviour

Run weighted A* with decreasing w and keep the best solution found. You get an answer immediately and improve it while time remains. This is how real-time planners behave.

IDA*: A* answers at iterative-deepening memory

A* keeps every generated node, so its memory is the bottleneck it was in module 2. IDA* runs depth-first search with an f-value cutoff, raising the cutoff to the smallest f that exceeded it, and repeating.

  • Memory: O(bd) — linear in depth.
  • Optimal with an admissible heuristic, like A*.
  • Re-expands nodes between iterations, which costs time but not memory.

When it is the right choice

Large state spaces with a strong heuristic and a tight memory budget — the 15-puzzle was solved this way long before machines had gigabytes.

When the heuristic is weak, the number of iterations explodes and IDA* becomes slower than A* by a large factor. The method inherits the quality of its heuristic.

§

Search algorithms are memory policies plus ordering policies. A* and IDA* share the ordering and differ only in what they keep.

Four mistakes that appear in almost every implementation

Four mistakes that appear in almost every implementation
MistakeSymptomFix
Recomputing g from the parent chain each timeCorrect but quadratic; the profile shows itStore g on the node when you generate it
Heuristic in the wrong unitsA* becomes uniform cost, or returns a suboptimal pathCheck that h is comparable to step cost, then test on a tiny case
Using a learned h without checking admissibilityFast, plausible, occasionally wrongClamp, or use weighted A* and accept the bound honestly
Stale frontier entries for the same stateExpands a state twice at different costsSkip on pop if the recorded g is worse than the stored best

The fourth is the one that bites in production. A priority queue does not support "decrease key" cheaply, so the usual pattern is to push duplicates and discard stale ones when they surface.

Key takeaways

  1. 1
    A heuristic is problem knowledge, made explicit.

    It is not part of the algorithm, and it decides whether the algorithm is usable.

  2. 2
    Admissibility ⟹ optimal tree-search A*.

    Because f on the optimal frontier is a lower bound on C*.

  3. 3
    Consistency ⟹ safe explored set.

    That is the condition you actually need with a hash set.

  4. 4
    Relax to invent, dominate to improve.

    Solve an easier problem for a bound; take the max of admissible bounds.

  5. 5
    Optimality is a choice with a price.

    Weighted A* buys speed with a stated bound of w.
