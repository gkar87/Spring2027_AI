Learning values from experience

Monte Carlo, TD and Q-learning: the model is gone.

What actually changed from module 6

That single change — no model — forces a different algorithmic strategy: estimate values from samples instead of computing them from equations.

Two ways to handle the missing model

  1. Learn the model, then plan inside it. Sample-efficient, but errors in the model compound.
  2. Learn the value directly, without ever writing T down. Simpler, but needs more interaction.

This module is mostly the second. The first returns whenever data is expensive and simulation is cheap.

Monte Carlo: wait for the end, then average

Run a full episode. At the end you know the actual return Gt from every state you visited. Average those returns over many episodes.

V(s) ← V(s) + α [ Gt − V(s) ]

The bracketed term is the error between what you predicted and what actually happened. The update moves the estimate toward the observation.

Properties

  • Unbiased: the return is the real thing, not an estimate of it.
  • High variance: one unlucky episode moves the average a lot.
  • Requires terminating episodes, or a finite horizon.
  • Cannot learn mid-episode — no update until the end.

That last property is fatal in continuing tasks, which is most of the world.

TD(0): bootstrap off your own estimate

Instead of waiting for the true return, use the reward you just received plus your current estimate of the next state:

V(s) ← V(s) + α [ r + γV(s′) − V(s) ]

The target r + γV(s′) is a bootstrapped estimate: it uses a guess to update a guess. That sounds circular, and it is — but the contraction property from module 6 is what makes it converge.

Lower variance means a larger learning rate is stable, which is why TD usually learns faster per episode even though each update is biased.

SARSA and Q-learning: two targets, one letter apart

SARSA — on-policy

Q(s,a) ← Q(s,a) + α[ r + γQ(s′,a′) − Q(s,a) ]

Uses the action a′ the agent actually took next, including exploratory ones. It learns the value of the policy it is following, so it is cautious when the policy is exploratory.

Q-learning — off-policy

Q(s,a) ← Q(s,a) + α[ r + γ·maxa′Q(s′,a′) − Q(s,a) ]

Uses the best possible next action, regardless of what it did. It learns the optimal policy while behaving exploratorily.

At a terminal s′ there is nothing to bootstrap from, so the target is just r.

The difference in behaviour

Next to a cliff, SARSA learns the safe path because its exploration sometimes walks off the edge and the value reflects that. Q-learning learns the optimal path along the edge, because max ignores the exploratory mistakes — and it may fall in during training.

Neither is "better". Q-learning is better if you will deploy the greedy policy; SARSA is better if exploration continues during operation.

Off-policy learning is what lets you reuse old data — the property deep RL depends on.

Worked Q-learning update

One step

A 2×2 grid. From (0,0) the agent moves right to (0,1) and receives r = 1. Let α = 0.5, γ = 0.9.

Current estimates: Q((0,0), right) = 0.2. From (0,1) the best action has Q = 4.0.

target = 1 + 0.9 × 4.0 = 4.6
Q ← 0.2 + 0.5 × (4.6 − 0.2) = 2.4

The most common exam error

Using γ on the reward as well as the value, or forgetting to subtract the old estimate. The update is old + α(target − old), and the subtraction is not optional.

Exploration and approximation

What it costs to look around, and what breaks at scale.

Exploration: the part with no free lunch

If the agent always takes the greedy action, it never discovers anything better. If it always explores, it never uses what it learned. Every method here is a different answer to that trade.

  • ε-greedy — random action with probability ε. Simple, and the default baseline.
  • Decaying ε — explore early, exploit later. Needs a schedule, which is a hyperparameter in disguise.
  • Optimistic initialization — start values high so every action looks worth trying once.
  • UCB — choose by value plus an uncertainty bonus.
UCB: a = argmaxa [ Q(a) + c√(ln N / na) ]

Why this is not just a trick

Exploration is an information problem, not a reward problem. The value of trying an action includes what you learn by trying it — and that value is invisible to a greedy rule.

Function approximation, and the deadly triad

A table needs one entry per state. For images, robot poses, or text, that is impossible. Replace the table with a parameterized function Vθ(s) and update θ instead.

This works, but it breaks the convergence guarantee. The combination of three ingredients can diverge:

Why the three together are unstable

Bootstrapping makes the target depend on the parameters you are updating, so the update is not a fixed-point iteration on a fixed function. Off-policy sampling changes the distribution the update is computed over. Approximation lets one update change values at many states at once, including ones you did not visit.

Remove any one and convergence results exist. Keep all three — as every deep RL system does — and you rely on engineering rather than theory.

DQN: two tricks that made deep RL work

Q-learning with a neural network on raw pixels diverged, because consecutive samples are correlated and the target moves with every update.

Experience replay

Store transitions in a buffer and sample random minibatches. This breaks the temporal correlation and lets one transition be reused many times.

Target network

Compute the bootstrap target with a frozen copy of the network, updated every few thousand steps. This stops the target from chasing the parameters.

L(θ) = E(s,a,r,s′)~D [ ( r + γ maxa′ Q(s′,a′; θ−)
  − Q(s,a; θ) )² ]

θ− are the frozen target parameters, and D is the replay buffer. Everything else is ordinary supervised regression.

Maximization bias

The max over noisy estimates is systematically optimistic. Double DQN fixes it by using the online network to choose the action and the target network to evaluate it.

Policies, rewards and honest evaluation

Policy gradients, PPO, reward design and reporting.

Policy gradients: optimize the policy directly

Value-based methods learn values and derive a policy. Policy-gradient methods parameterize the policy πθ(a|s) and ascend the expected return directly.

∇J(θ) = E[ ∇ log πθ(a|s) · G ]

The intuition: raise the probability of actions that led to high return, lower it for actions that did not. The log-derivative is just the direction in which to move the parameters to make that action more likely.

Variance is the problem

Raw return G varies enormously between episodes, so the gradient estimate is noisy. Two fixes:

  • Baseline — subtract V(s); this does not bias the gradient and cuts variance sharply.
  • Actor–critic — use a learned critic for the baseline, so the update uses an advantage instead of a raw return.
advantage: A(s,a) = Q(s,a) − V(s)

PPO: keep the new policy close to the old one

A large policy update can destroy a good policy and never recover. Trust-region methods bound how far one update may move; PPO does it with a clipped objective, which is cheaper.

L = E[ min( rt(θ)At, clip(rt(θ), 1−ε, 1+ε)At ) ]

where rt(θ) is the probability ratio between the new and old policy. Once the ratio leaves the clip range, the gradient stops — the update is penalized for moving too far.

Why it became the default

  • It works across continuous and discrete actions with the same code.
  • It is robust to hyperparameters, which matters more than peak performance.
  • It is simple enough to implement correctly in an afternoon.

Reward design is where RL projects fail

An optimizer maximizes exactly what you wrote, including the parts you did not think about. Three failure patterns:

  • Reward hacking — the agent exploits a loophole: a boat racing game that spins in circles collecting points instead of finishing.
  • Sparse reward — nothing to learn from until success, which may never come.
  • Proxy mismatch — you reward clicks but wanted satisfaction.

Practical mitigations

  • Shape rewards with potential functions, which preserve the optimal policy if done correctly.
  • Test the reward on a hand-written policy before training anything.
  • Inspect rollouts, not just the learning curve.
  • Keep a held-out evaluation that the reward does not see.
§

Look at what the agent actually does. A rising reward curve is not evidence of the behaviour you wanted — it is evidence of the behaviour you specified.

How to evaluate an RL result honestly

RL results are among the least reproducible in machine learning. A single learning curve is close to meaningless.

  • Report at least five seeds, with mean and spread.
  • Report the evaluation protocol: how many episodes, which policy, what exploration.
  • Report environment steps, not wall-clock time.
  • Report the baseline: random, and a tuned simple method.

The seed question

Two runs of the same algorithm with different seeds can differ by more than two different algorithms do. If a paper's improvement is smaller than its seed variance, the improvement is not established.

Key takeaways

  1. 1
    All three rules differ only in their target.

    Monte Carlo uses the return, TD uses one reward plus a guess, SARSA and Q-learning differ by max.

  2. 2
    Bootstrapping trades bias for variance.

    That trade is why TD learns faster per episode than Monte Carlo.

  3. 3
    Exploration is an information problem.

    UCB makes the value of information explicit.

  4. 4
    Deep RL works by engineering, not by theorem.

    Replay and target networks exist because the deadly triad cannot be proven stable.

  5. 5
    You get the reward you wrote.

    Inspect behaviour, use multiple seeds, and keep an evaluation the optimizer cannot see.
